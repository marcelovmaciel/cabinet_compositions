L199: # Eleições Brasil
L200: 
L201: Esse repositório de código contém programas que baixam dados do Tribunal Superior Eleitoral, normalizam, agrupam e limpam. Atualmente as bases de dados disponíveis são:
L202: 
L203:   * Candidaturas (1996 a 2020)
L204:   * Bens declarados (2006 a 2020)
L205:   * Votação por zona eleitoral (1996 a 2020)
L206:   * Prestação de contas (2002 a 2020)
L207: ## Metodologia
L208: 
L209: A fonte primária é o cite109†Repositório de Dados Eleitorais do TSE†www.tse.jus.br . O processo é o seguinte:
L210: 
L211:   * Baixar arquivos ZIP
L212:   * Para cada ZIP, extrair (em memória) os arquivos internos
L213:   * Para cada arquivo interno, processá-lo (identificar cabeçalho, limpar)
L214:   * Juntar todos os resultados em um arquivo
L215: ## Normalização
L216: 
L217: Algumas etapas de normalização são necessárias para facilitar análises e conversões dos dados, como:
L218:   * Retirar todos os acentos: alguns nomes aparecem com acentos em um ano e sem em outros, dificultando muito os agrupamentos;
L219:   * Representar valores indisponíveis como células em branco: `#NULO` e `#NULO#` indicam informação em branco na base do TSE; `#NE` e `#NE#`, informação que não era registrada naquele ano; e, nos dados de candidatura, `NÃO DIVULGÁVEL` (ou `Não divulgável`), `-4`, `-1` e `-3` (sentinelas numéricas do TSE para nulo e não aplicável). Embora tenham origens distintas, todos ficam como nulas/vazias no CSV final, facilitando análises e reduzindo o tamanho do arquivo;
L220:   * Normalização dos códigos de cargo: os códigos de cargo variam para alguns anos, tornando difícil o agrupamento entre anos e, para facilitar as análises, normalizamos todos os anos;
L221:   * Renomear colunas: nem todas as colunas possuem nomes intuitivos e foram renomeadas (exemplo: `COD_SIT_TOT_TURNO` foi renomeado para `codigo_totalizacao_turno`). Para saber mais detalhes sobre as colunas que foram renomeadas, olhe os arquivos no diretório `headers/` (caso você altere algum desses arquivos, gere novamente os cabeçalhos finais com `python tse.py headers`). Em tabelas e saídas novas:
L222:     * Campos do próprio registro: não repetem o nome da tabela (ex.: `nome_urna`).
L223:     * Campos de entidades externas: são prefixados com o nome da entidade (ex.: `partido_sigla`, `partido_numero`, `eleicao_codigo`, `fornecedor_cpf_cnpj`, `fornecedor_nome`) para garantir que colunas da mesma entidade fiquem agrupadas em ordem alfabética.
L224:     * A tabela histórica `candidatura` preserva seus nomes originais por compatibilidade com sistemas legados.
L225: > Nota: nem todos os códigos/descrição foram normalizados (alguns apresentam inconsistências ainda não resolvidas e serão feitos em breve).
L226: ## Instalando
L227: 
L228: Os programas requerem Python 3.7+. Instale as dependências executando:
L229: 
L230:     pip install -r requirements.txt
L231: ## Rodando com containers
L232: 
L233: Para rodar o projeto sem instalar Python e suas dependências na máquina, são necessários Docker, Docker Compose v2 e `make`. O `compose.yml` monta o diretório do projeto em `/app`; portanto, os arquivos baixados e gerados pelo container permanecem no diretório local `data/`.
L234: 
L235: Construa a imagem de desenvolvimento antes do primeiro uso:
L236: 
L237:     make build
L238: Execute uma extração passando os argumentos de `tse.py` em `ARGS`:
L239: 
L240:     make tse ARGS='candidatura --years=2014,2018'
L241:     make tse ARGS='candidatura --use-mirror'
L242: 
L243: Para executar todas as extrações previstas em `run.sh`:
L244: 
L245:     make run
L246: 
L247: Também é possível executar um comando diretamente pelo Compose:
L248: 
L249:     docker compose run --rm main python tse.py candidatura --years=2014,2018
L250: Os comandos de desenvolvimento são executados no mesmo container:
L251: 
L252:     make test
L253:     make lint-check
L254:     make lint
L255:     make bash
L256: 
L257: Use `make help` para listar todos os atalhos. Para reconstruir a imagem sem reutilizar camadas, execute `make build-no-cache`.
L258: ## Rodando
L259: 
L260: O script `tse.py` baixa, trata e extrai os dados. Basta rodá-lo, passando que tipo de dado quer baixar/tratar/extrair:
L261: 
L262:     python tse.py candidatura
L263:     python tse.py bem_declarado
L264:     python tse.py votacao_zona
L265:     python tse.py receita
L266:     python tse.py despesa
L267: 
L268: Os dados ficarão disponíveis em:
L269: 
L270:   * `data/download/`: arquivos originais baixados, por ano
L271:   * `data/output/`: arquivos extraídos (agrupados por tipo)
L272: Caso queira converter os arquivos `.csv.gz` gerados em um banco de dados SQLite (facilita as análises), execute:
L273: 
L274:     ./csv2sqlite.sh
L275: 
L276: Esse script irá rodar o comando `rows csv-to-sqlite` em todos os arquivos gerados em `data/output` e criará o arquivo `data/eleicoes-brasil.sqlite`.
L277: ### Opções
L278: 
L279: As opções listadas abaixo podem ser utilizadas em conjunto.
L280: 
L281: #### Anos
L282: 
L283: Você pode especificar para quais anos deseja a extração (separados por vírgulas), como em:
L284: 
L285:     python tse.py candidatura --years=2014,2018
L286: #### Alterar fonte dos dados
L287: Como os servidores do TSE podem estar lentos em épocas de eleição, você pode baixar os dados de algum servidor mais rápido que hospede uma cópia deles (chamamos de mirror).
L288: No Brasil.IO mantemos um mirror de alguns arquivos do Repositório de Dados Eleitorais do TSE, porém note que ainda não temos uma política de atualização frequente desses dados e, por isso, eles podem estar desatualizados (estamos trabalhando para que sejam atualizados com mais frequência e que a data de cópia dos dados fique explícita em uma página).
L289: Para que o script colete os daos usando nosso mirror, execute-o com a opção `--use-mirror`:
L290: 
L291:     python tse.py candidatura --use-mirror
L292: 
L293: Você pode especificar também a URL base do mirror, que por padrão é do cite110†Brasil.IO†brasil.io :
L294: 
L295:     python tse.py candidatura --use-mirror --mirror-url=https://data.brasil.io/mirror/eleicoes-brasil/
L296: #### Apenas baixar
L297: 
L298: Caso queira apenas baixar os arquivos, utilize a opção `--download-only`.
L299: 
L300: #### Forçar download
L301: 
L302: Por padrão, caso os arquivos necessários para uma extração já existam em `data/download/`, eles não serão baixados novamente. Você pode utilizar a opção `--force-redownload` para que eles sejam deletados e baixados novamente.
L303: #### Arquivo de saída
L304: 
L305: Você pode especificar o arquivo de saída (que será sempre um CSV, mas pode estar compactado):
L306: 
L307:     python tse.py candidatura --output=candidatura.csv.gz
L308: 
L309: #### Observações
L310: 
L311: Em alguns casos o TSE libera arquivos compactados no formato RAR (mesmo com a extensão ".zip"). Para extrair os dados desses arquivos você precisa instalar em seu sistema o bsdtar ou unrar (em sistemas Debian e derivados): `apt install libarchive-tools` ou `apt install unrar` - o último não é software livre).
L312: ## Links do DivulgaCandContas
L313: 
L314: Use `url_candidatura` para montar a página pública de uma linha de `candidatura.csv.gz`:
L315: 
L316:     from divulgacandcontas import url_candidatura
L317: 
L318:     url = url_candidatura(linha)
L319: A função usa `ano`, `numero_sequencial`, `sigla_unidade_federativa` e `sigla_unidade_eleitoral`. Nota: o `codigo_eleicao` do CSV não é o identificador usado pelo DivulgaCandContas: nas eleições ordinárias o identificador é mapeado pelo ano. Para uma `ELEICAO SUPLEMENTAR`, consulte o ID no endpoint `/divulga/rest/v1/eleicao/suplementares/{ano}/{uf}` do TSE e informe-o como `codigo_eleicao_divulgacand`.
